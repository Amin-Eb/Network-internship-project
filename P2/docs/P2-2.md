# DnsTransaction Reporter

## Former Aproach
The way was far from wanted usecases and design that mentor considered.
the code wasnt direct consumer of packets and it was reading packets one by one from file using pcap++, couldnt work with raw binary packets.

## New Aproach

### Design

We designed the new DnsAnalyzer class which consumes Binary packets with :
```
    void addBinary(const Binary& bin);
```
and can be used in diffrent streams.
** encapsulation ** done in decleration of fields and functions, so that Only meaningful operations (addBinary, addDnsTransaction, getReport) are public.

first simple idea was exporting metadata of dns requests and responses by reading some specific fixed bytes of packets.
for example searching for transactionID of packet in [62-63] bytes, but it didnt work because size of other layers data before dns layer may vary.
so i used ** pcap++ ** for converting raw binary data to workable packets and exported metadata from those packets.

### Dependencies
- gtest (Google Test) – for unit testing
- PcapPlusPlus – for packet parsing
- C++17 standard library (STL)
- arpanet - for clean hex ids of packets

dependencies are handled by conan.

### Build

Create the build directory in root of project and then :
```
cd build
cmake -DENABLE_COVERAGE=ON ..
cmake --build .
ctest --output-on-failure
```

By this you can run test/test_dns.cpp to figure out functionality of class.
The test itself uses pcap++ to change packets from capture.pcapng to raw binary packets and pass those one by one to the DnsAnalyzer.

* While developing the DnsAnalyzer i decided not to use main.cpp or so for testing the functions, i started TDD aproach for measure functionality of written codes.
* We used pcap++ among all other usable libs or parsing by ourselves because :
      - Direct support for reading .pcap and .pcapng capture files without additional parsing logic.
      - Exporing metadata in so easy ways.
      - More and better documentation.
